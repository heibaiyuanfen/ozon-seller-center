# 低 token 与零 token 跟卖上架方案

## 已实现：原图直传

自动工作台可选择原图直传，跳过生图和水印。每件新任务固定保存图片模式，支持多店铺和后台独立进程。原图仍上传自有 OSS，原来的图片下载检查与去重保留。

当前文案和属性 AI 没有停用：跟卖的属性映射仍可能调用视觉分析，本地新品仍需视觉分析识别商品。因此仅图片制作部分免调用生图模型，不能宣称全流程零 token。

## 下一步：低 token 模式（尚未实现）

1. 用来源已有俄文标题、描述、参数构建结构化事实。能直接复用的文字不改写，标签用固定规则清理，缺少标签时允许省略可选标签。
2. 按已选类目加载官方属性定义与字典，先用人工模板、精确匹配、已确认映射填写，最后仅把不能匹配的字段交给 AI。不要发送整棵类目树、全部字典和完整页面。
3. 图片只有在确实缺少关键可见事实时才分析，优先选 1 张清晰图，避免常规任务每次分析 6 张。认证、材料等不能凭图片确定的属性转人工确认。
4. 同一来源变体、事实摘要、类目、提示词版本、模型和语言一致时复用结果。多店铺只独立计算价格、库存、货号，不重复生成通用资料。
5. 为调用记录输入输出 token、耗时和缓存命中；服务不返回 usage 时标记未知，不能填零。比较每件审核合格商品的实际成本。

## 零 AI token 模式（尚未实现）

路径：采集俄文内容与原图 → 规则清洗 → 人工类目模板 → 字典精确匹配 → 人工补齐未确认必填项 → 本地核价与校验 → 原图 OSS 上传 → Ozon 提交 → 查询导入结果 → 库存与台账。

- 不创建任何 AI 客户端、不请求文案/视觉/生图服务；AI 配置为空时也能运行。
- 来源文字和人工维护的俄文模板可直接复用；中文等其他语言内容需要人工提供俄文或使用另行部署的本地翻译模型。本地模型无云端 token 账单，但仍占用硬件和时间。
- 模板保存类目 ID、类型 ID、已核实通用属性与映射规则。型号、净重、规格、材料等产品事实不能盲目继承。字典 ID 仍按当前平台规则校验。
- AI 无法处理的必填项改为“待人工补充”，不杜撰、不默认通过。适合同类目、参数规则固定、来源资料完整的商品。
- 提供总开关并测试所有入口：自动队列、手动上架、任务修复、多店铺。不能只关闭生图而遗漏属性中的视觉调用。

零 AI token 不等于零成本：OSS、网络、采集工具、平台费用及人工仍可能产生费用。也不保证比自动 AI 模式更快，资料不完整时人工补齐会成为瓶颈。

## 实施顺序与验收

先实现俄文内容直接复用，再做类目模板与精确字典映射，最后接入零 AI token 队列入口。将待补齐商品与可提交商品分开，批量审核后入队。

用同一批资料完整与不完整的商品分别比较：每件人工分钟数、AI 调用/token、从入队到库存完成的耗时、首次导入成功率。零 token 模式必须验证 AI 请求数为 0，且缺少必填属性时确实停止提交。保留现有取消、断点续跑和导入任务 ID 防重复机制。
