# 云端数据库设计与接入

## 当前结论

本项目采用 **Supabase（PostgreSQL + Auth + Storage）** 作为云端同步目标，本地 JSON、Excel 和图片目录继续作为离线数据源。第一版数据库结构已放在：

- `supabase/config.toml`：本地 Supabase 开发配置。
- `supabase/migrations/202609070001_initial_cloud_schema.sql`：表、索引、权限和图片桶。

仓库内只有可复现的数据库定义，尚未绑定任何个人 Supabase 账号。创建线上项目后执行迁移即可建立数据库。

## 数据边界

会同步：

- 非敏感店铺标识和名称；
- Ozon/WB 产品台账；
- 自动上架任务及断点；
- Seerfar 选品池和人工匹配字段；
- 美客多草稿；
- 用户明确选择上传的商品图片。

不会同步：

- Ozon Client-Id、Api-Key；
- WB Token；
- 美客多 Access Token / Client Secret；
- AI 与 OSS 密钥、代理账号；
- `config.json`、浏览器登录资料、Cookie；
- 仅对本机有效的绝对文件路径。

这些秘密继续留在每台电脑的本地 `config.json`，未来如需跨设备共享，应接入专门的密钥管理服务，而不是写入业务表。

## 表结构

| 表 | 用途 | 本地来源 |
|---|---|---|
| `workspaces` | 一个团队/数据空间 | 首次登录创建 |
| `workspace_members` | 成员及 owner/editor/viewer 权限 | 云端管理 |
| `devices` | 同步设备身份与最后在线时间 | 每台客户端生成 UUID |
| `shops` | 三个平台的非敏感店铺身份 | `config.json` 的安全字段 |
| `products` | 统一产品台账；常用字段独立列，其余放 `ledger` | `产品台账.xlsx` |
| `listing_jobs` | Ozon/WB/美客多任务和断点 | `auto_jobs.json`、`wb_job.json`、计划文件 |
| `product_pool_items` | 选品结果及人工匹配 | `选品池.json` |
| `mercadolibre_drafts` | 美客多商品家族草稿 | `mercadolibre-data/products/*/draft.json` |
| `sync_conflicts` | 无法自动合并时保留双方版本 | 同步器产生 |
| Storage `product-images` | 私有商品图片 | 用户选择的本地图片 |

所有业务表都带 `workspace_id`。可同步实体带 `revision`、`updated_at`、`source_device_id` 和 `deleted_at`，用于乐观锁、增量拉取、来源追踪和软删除。

## 建立线上数据库

1. 在 Supabase 控制台创建项目，记下 Project Ref、Project URL 和 anon key。
2. 安装 Supabase CLI 并在仓库根目录登录：

   ```powershell
   supabase login
   supabase link --project-ref <PROJECT_REF>
   supabase db push
   ```

3. 在 Authentication 中选择登录方式。内测阶段建议只允许邀请用户或关闭公开注册。
4. 桌面程序首次登录后，通过 RPC 创建工作空间：

   ```http
   POST /rest/v1/rpc/create_workspace
   Authorization: Bearer <USER_ACCESS_TOKEN>
   apikey: <ANON_KEY>
   Content-Type: application/json

   {"workspace_name":"我的上品团队"}
   ```

5. 只在本机配置 Project URL、anon key 和用户会话。`service_role` key 拥有绕过行级权限的能力，绝不能放入桌面程序。

本地验证（需要 Docker）：

```powershell
supabase start
supabase db reset
supabase status
```

## 客户端同步协议

同步器应在独立后台线程工作，不能阻塞 Tkinter 主线程。

1. 客户端首次运行生成并永久保存 `device_key`（UUID），在 `devices` 中注册。
2. 先上传本地更改，再按 `(updated_at, id)` 游标分页拉取远端更改；不要只用时间戳作为游标。
3. 更新时携带已知 `revision`，请求条件同时限制 `id` 和旧 `revision`。成功写入时将 revision 加一。
4. 如果更新影响 0 行，说明远端已改变：读取远端版本，并将双方内容写入 `sync_conflicts`，不要静默覆盖。
5. 删除使用 `deleted_at` 软删除并同步；所有设备确认后才能由维护任务物理清理。
6. JSON payload 必须先剔除密钥、Token、Cookie 和本地绝对路径。
7. 图片对象键固定为 `<workspace_id>/<platform>/<entity_id>/<sha256>.<ext>`；先按哈希去重，再上传。

建议保存本地同步状态：

```json
{
  "schema_version": 1,
  "device_key": "本机生成的 UUID",
  "workspace_id": "云端 workspace UUID",
  "cursors": {
    "products": {"updated_at": "2026-09-07T12:00:00Z", "id": "UUID"}
  }
}
```

## 合并规则

- 产品台账主键语义：`workspace + platform + shop + offer_id`。
- 店铺主键语义：`workspace + platform + local_id`。
- 选品池主键语义：`workspace + source + source_key`，Seerfar 首选 Ozon SKU 作为 `source_key`。
- 任务和草稿默认整条记录做乐观锁，不进行 JSON 字段级自动合并。
- Excel 台账仍作为本地展示/导出格式，不应成为两台电脑之间的冲突解决依据。
- 冲突优先人工选择“保留本地 / 保留云端 / 复制为新记录”。

## 行级权限（RLS）

迁移默认开启 RLS：

- viewer 只读；
- editor 可读写工作空间内业务数据；
- owner 可管理成员并读写数据；
- 未登录用户不能访问任何业务数据；
- Storage 根据对象路径第一段的 workspace UUID 检查成员身份。

应用端权限不是安全边界，所有访问仍由数据库 RLS 检查。

## 备份与运维

- 开启 Supabase 数据库备份；上线前确认所选套餐的备份保留期。
- 每次改表都新增迁移文件，已部署的迁移禁止直接修改。
- 至少每季度做一次恢复演练。
- 监控数据库容量、Storage 容量、失败登录和同步冲突数量。
- 客户端日志只记录请求 ID、状态码和实体 ID，不记录 Token 或完整敏感 payload。
