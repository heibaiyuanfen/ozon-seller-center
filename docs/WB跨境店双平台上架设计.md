# Ozon + WB 跨境店双平台上架设计（初稿）

## 入口和范围
在 Ozon 待发布批次添加目标选项「仅 Ozon」（默认）和「Ozon + WB 跨境店」。选择后者时选择 WB 店铺、仓库和价格模板，预览逐行列出 WB 类目、缺项、结算币种、售价和分配库存。首版实现首次发布，持续调价、共享库存及订单履约另行设计。

## 对接现有软件
在提交批次时冻结商品快照并持久化两个平台任务，避免依赖 Ozon 成功回调才取得商品。评估复用 catalog_upload.product_data 提取公共资料，WB 分支复用 wb.py 的 build_card_payload、WildberriesApi 和 WbListingWorkflow.advance。Ozon 的结果与 WB 的结果分列展示。

|来源资料|WB 草稿处理|
|---|---|
|内部商品编号、规格|按店铺保存稳定 vendorCode、规格条码、平台 nmID 和 chrtID 的映射。首版仅自动处理单规格，多规格进入待处理|
|Ozon 类目和属性|复用已确认的类目映射，按 WB subjectID 读取属性定义、枚举和必填项，缺项显示在该商品行|
|商品名、描述、品牌、图片|沿用已核实的商品事实与可用图片，按 WB 字段限制预检。仅有 Ozon 卡号的商品先补资料|
|包装尺寸和重量|保留原单位，转为 WB 接口单位，未知值留待补齐|
|采购成本和可售量|按 WB 店铺币种、运费和费用计算售价。双平台库存分配合计不得超出可用量|

## 发布与恢复
以店铺、内部 SKU 和平台建立唯一任务，提交前持久化 vendorCode。按“校验 → 提交建卡 → 查卡或错误列表 → 图片 → 价格任务确认 → 仓库库存 → 完成”推进。保存步骤、平台标识、价格任务号、重试时间和错误。提交超时先按 vendorCode 对账，未确定结果时保持待确认；卡号冲突转人工核对。限流按服务退避，字段错误返回草稿。仅对未完成平台和步骤续跑。价格未确认前不能投放库存。

## 官方资料与跨境店验证
WB 官方更新列出 POST /content/v2/cards/upload、/content/v2/get/cards/list 和 /content/v2/cards/error/list。涉及强制标识的商品需核对 needKiz，只有商家确实已标识才提交 kizMarked。来源：[WB 官方 API 更新](https://dev.wildberries.ru/en/release-notes?id=392)。

当前客户端使用 wildberries.ru 系列域名。跨境店实际可用域名、Token 权限、价格币种和可用仓库仍须按目标店铺核实；接入时先查询卖家信息、类目和仓库，再使用一个已核实 SKU 验证建卡、价格回读和库存。通过后开放批量发布。

## 验收
覆盖仅 Ozon 旧任务、双平台正常发布、WB 缺少必填项、建卡响应丢失、应用重启、价格被拒和重复提交。检查平台结果独立、重复执行只有一张目标卡、失败可定位到字段或步骤，以及 WB 实际售价币种和仓库库存与预览一致。
